FLIGHT DECK ORIENTATION
What does this actually do?

      
It runs repeatable stories about servers failing, retrying, and recovering. You move through the story event by event; the right side explains why each event happened and whether a correctness rule still holds.

      

        
WORKLOADA real-world story, such as a payment or model rollout.

        
EVENTOne meaningful action: append, persist, timeout, retry, or commit.

        
QUORUMThe majority needed before a replicated change is safe.

        
INVARIANTA rule that must never break, such as “charge only once.”

      

      

        EXAMPLE · RESPONSE LOST AFTER COMMIT
        
Checkout sends pay-7→2 of 3 servers persist it→Reply packet disappears→Checkout retries pay-7→Saved result is returned

        
The request ID is stored with the charge. On retry, the processor finds that ID and returns the first result instead of charging again.
